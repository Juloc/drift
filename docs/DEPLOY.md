# Deploying the preview (nothing here is done by this repository)

The owner's stack repository takes `deploy/stack/docker-compose.yml`; the image comes from the release workflow. Nothing is pushed from a developer's machine.

## What was built and tried

- `Dockerfile` (the one of the base template; it also carries `game/`, `vendor/three/` and `server/Relay/`) builds a 352 MB image.
- `.github/workflows/release.yml`: on a tag `vX.Y.Z` that equals the `<Version>` in `Directory.Build.props` it builds and pushes `ghcr.io/juloc/drift:X.Y.Z` (actions pinned by commit, fewest permissions; the digest goes to the run's summary).
- `deploy/stack/docker-compose.yml`: stack name `drift`, three services (`init` runs once, `db` PostgreSQL 18, `app`), one volume `data` that holds the database, the server's key file and the database password. **No variable, no `.env`, no secret in the file**: the init step writes a random password into the volume at the first start. The only published port is `8110` (the app's 8080) on the Docker host, like the other stacks.
- **Tried locally** with the image built from this tree and the stack file (the port published on the machine's loopback only, for the test) (a throwaway project, removed afterwards): all three containers healthy; `/api/health` answers `{"ok":true,"db":true,"app":"drift","version":"0.2.0","base":"0.3.4","status":"ok"}`; 20 migrations applied; the game page `/play/`, its scripts and data, `/vendor/three/...` (also the GLTFLoader), `/games/`, `/legal/privacy.html`, `/g/` and the model file (`.glb`) are served; the first account is made with the setup code from the log; a **guest link** works and a guest and the hub person both receive the relay's welcome and roster on `/api/guest/ws` and `/api/play/ws`; sign-up of a games account answers `403 games.signup_closed` as it must (see below).

## What the owner needs

1. **Stack and image.** Put `deploy/stack/docker-compose.yml` into the stack repository as the stack `drift`; the tag in it (`0.2.0`) is the version of the release. To publish: tag `v0.2.0` in the repository (the owner's yes; the workflow does the rest). The package `ghcr.io/juloc/drift` must be readable by the machine (public, or a login on the machine).
2. **Caddy.** One route for the preview's public host name to the app on the Docker host, port **8110** (a plain `reverse_proxy`; WebSockets pass through by default). Caddy runs in a container of its own and reaches the apps through the published host ports, so it comes from a Docker network, that is a **private network**. The app believes `X-Forwarded-For`, `-Proto` and `-Host` from private networks as long as the instance setting `proxy.trusted` is not set (the default), which is exactly this case; Caddy sets the three headers itself. Every limit counts by address, so this matters. **Be aware:** because the port is published on the host, a device in the same local network can also reach it directly and could send a faked `X-Forwarded-For` (the same is true of the other apps behind this Caddy). If that is not wanted, the administrator sets `proxy.trusted` in the settings to Caddy's Docker address only. `__Host-` cookies need HTTPS; Caddy's `X-Forwarded-Proto: https` makes them.
3. **The first account.** `docker compose logs app` shows a setup code once; opening the address and entering it makes the administrator (name, password, an authenticator): that is the owner. The family comes in through the hub (JulOS) as before; the **guest links** (settings) let a friend in for some hours.
4. **Sign-up of strangers stays closed on purpose.** The pages `legal/privacy.html` and `legal/imprint.html` (`src/Drift/wwwroot/legal/`) still carry the marker `[[OWNER-TEXT]]`; the log says so at every start (`Sign-up for games accounts is CLOSED`). When the owner's two texts replace the marker, registration opens by itself (a new image, or the files replaced in the image).
5. **A name list (optional).** `games-names.txt` next to the app (one word per line) adds to the built-in name filter; in the container that would be a file in the image or a mounted one: not set up, the built-in list is used.
6. **Backups.** Back up the volume `data` (everything is in it). A restore was not tried yet (planned for the load-test step).
7. **Not checked here:** HTTPS (the cookie names `__Host-...` need it; behind Caddy the proxy's `X-Forwarded-Proto: https` makes them), the real public name, the memory and CPU of the container under load (the 64-driver numbers are in `docs/STATE.md`), and the first start on the owner's machine (arm64 or amd64: the image is plain .NET and builds for the machine's platform).
